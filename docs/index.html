filebox

A home file server on an old PC. Family members upload and download files over SFTP or from a website. You manage everything from an admin panel that is only reachable over Tailscale.

What you get

PartWho uses itHow it is reached
SFTP serverFamily, with any SFTP appPublic, port 2222, files.thijssensoftware.nl
Web portalFamily, from any browser or phonePublic, port 443 (HTTPS), same address
Admin panelYouOnly over your Tailscale network, port 8443

Every family member has their own private folder and cannot see anyone else's. The admin panel creates users, shows disk health and logs, and lets you browse everything.

What you need

  • A spare PC that can stay on, with Debian 13 (Debian 12 also works, but the web portal certificate needs 13).
  • An SSH key on your own computer, to log in to the box.
  • A free Tailscale account.
  • The domain thijssensoftware.nl in DigitalOcean DNS, and a DigitalOcean token that is limited to domain records.
  • Access to your router to forward two ports.

Replacing Windows on the old PC

Back up first. Copy anything you care about to an external drive before changing partitions.

Option A: the wizard (UEFI PC)

Download installer/ from the repository, open PowerShell as Administrator in that folder and run .\Install-Filebox.ps1 -DryRun first to see what it would do. Then run it without -DryRun. It asks which partition Debian replaces and which one holds your data, downloads and checks the installers, adds a one-time boot entry and restarts into an unattended install. .\Install-Filebox.ps1 -Rollback undoes it before the restart. It refuses BitLocker partitions and never touches the data partition. A cable is the most reliable connection. Without one it uses Wi-Fi (WPA or WPA2 with a password, not WPA3-only networks), and it can also set up Wi-Fi alongside a cable so you can move the PC later. The Wi-Fi password is stored as plain text, readable only by root. It has been tested in a virtual machine, not yet on real hardware, and Wi-Fi has never been tested on a real radio.

Option B: by hand

  1. Open Disk Management in Windows and note which partition holds the data and what filesystem it uses.
  2. If the data partition is NTFS or exFAT, filebox cannot use it as it is. SFTP users live in root-owned folders with Linux permissions, and NTFS cannot hold those. Copy the data off, format that partition as btrfs in the Debian installer, and copy it back after setup.
  3. If it is already ext4, you can leave it alone, but it cannot become a mirror later without copying everything off and back.
  4. Install Debian 13 from a USB stick (netinst). Choose manual partitioning, install onto the old Windows partition (plus the EFI partition on UEFI machines), and do not format the data partition. Select only "SSH server" and "standard system utilities".
  5. Mount the data partition at /srv/sftp before running setup. Find its UUID with lsblk -f, add this line to /etc/fstab, then run sudo mount -a: 
    UUID=<uuid> /srv/sftp btrfs defaults,nofail 0 2

Install

1. Put your SSH key on the box

From your own computer: ssh-copy-id youruser@<box-ip>. Setup refuses to continue without a key, because it turns password login off.

2. Download the release and check it

curl -fLO https://github.com/Ezomic/filebox/releases/latest/download/filebox-panel
curl -fLO https://github.com/Ezomic/filebox/releases/latest/download/filebox-panel.sha256
curl -fLO https://github.com/Ezomic/filebox/releases/latest/download/deploy.tar.gz
curl -fLO https://github.com/Ezomic/filebox/releases/latest/download/deploy.tar.gz.sha256
sha256sum -c filebox-panel.sha256 deploy.tar.gz.sha256
tar -xzf deploy.tar.gz

3. Run setup

cd deploy
sudo ./setup.sh ../filebox-panel

It installs and configures SSH, the firewall, fail2ban, Tailscale, the admin panel and the DNS updater. It is safe to run again at any time.

4. Join Tailscale

sudo tailscale up

Open the login link it prints. Install Tailscale on your own computer too.

5. Create the admin account

On the box, read the one-time token:

sudo cat /var/lib/filebox/setup-token

Then, from a device on your tailnet, open https://<tailscale ip of the box>:8443/setup, enter the token and choose a password of at least 12 characters. Your browser warns about the certificate because it is self-signed. That is expected for this admin address.

6. Point the domain at your home

umask 077 && read -rsp 'token: ' t && printf %s "$t" | sudo tee /etc/filebox/do-token >/dev/null; unset t
sudo systemctl start filebox-dns.service

This keeps files.thijssensoftware.nl pointed at your current home IP address, even when your provider changes it.

7. Router

Forward TCP 2222 (SFTP) and TCP 443 (web portal), IPv4, to the box. Never forward 8443.

8. Close the LAN SSH door

When you have confirmed you can log in to the box over Tailscale, run setup once more with LAN SSH switched off:

sudo LAN_SSH_CIDRS="" ./setup.sh ../filebox-panel

9. Add your family

In the admin panel, open Users and create one account per person. Move any existing files into /srv/sftp/<name>/files/ afterwards, then run sudo chown -R <name>:sftpusers /srv/sftp/<name>/files.

Turn on the web portal

The portal starts by itself once it has a certificate. This needs step 6 (the DigitalOcean token) first.

sudo filebox-portal-cert issue you@example.com

Running this accepts the Let's Encrypt terms of service. Your email is only used for expiry notices. When it finishes, https://files.thijssensoftware.nl shows a sign-in page. Family sign in with the same username and password they use for SFTP.

  • The certificate renews itself (a daily timer checks it); the panel picks up the new one without a restart.
  • The admin dashboard shows how many days the certificate has left.
  • Family can change their own password on the portal. You can also change it in the admin panel, which signs them out of the website.
The portal must be exposed directly. Do not put it behind a reverse proxy, because it identifies visitors by their connecting address.

Add a second disk (RAID1 mirror)

With one disk, a dead disk loses everything. A data partition on btrfs becomes a mirror in place, while the server keeps running. A mirror protects against a dead disk, not against deleting a file: the delete happens on both disks.

Check the device name with lsblk. The disk you add is erased.

The mirror holds as much as the smaller of the two disks. Converting can take hours on a full disk.

sudo btrfs device add /dev/sdX /srv/sftp
sudo btrfs balance start -dconvert=raid1 -mconvert=raid1 /srv/sftp
sudo btrfs filesystem df /srv/sftp

The last command should say RAID1 on every line. A monthly check (filebox-scrub.timer) finds damaged files and repairs them from the other disk. See the result with sudo btrfs scrub status /srv/sftp.

If a mirror disk dies, /srv/sftp will not mount by itself, so logins fail until you act. Your files are safe on the other disk. Mount it, then replace the dead disk (devid comes from btrfs filesystem show):

sudo mount -o degraded /dev/sdY /srv/sftp
sudo btrfs replace start <devid> /dev/sdX /srv/sftp

Update

One command on the box:

sudo filebox-update

It finds the latest release, downloads the binary and the setup files, checks both against their published checksums, keeps the old binary as a backup, and re-runs setup. Your users, files, admin password, Tailscale login and certificate are untouched. The panel restarts, so people have to sign in again. SFTP keeps running.

CommandWhat it does
sudo filebox-updateInstall the latest release
sudo filebox-update v0.2.0Install a specific release
sudo filebox-update rollbackPut the previous binary back
filebox-panel -versionShow the installed version (also at the bottom of the admin dashboard)
The first release that contains filebox-update must be installed by hand once (steps 2 and 3 above). From then on, use the command.

When something is wrong

ProblemWhat to do
Cannot open the admin panelCheck Tailscale is running on both devices. The panel only listens on the Tailscale address, port 8443.
A family member is "locked out"After a few wrong passwords an address is blocked for a while. Wait 15 minutes, or unban it: sudo fail2ban-client set filebox-portal unbanip <ip> (SFTP uses the jail sshd).
Web portal does not loadRun sudo filebox-portal-cert issue you@example.com if you have not yet, check the router forwards 443, and look at sudo journalctl -u filebox-panel -n 50.
Domain points to the wrong IPsudo systemctl start filebox-dns.service and check sudo journalctl -u filebox-dns -n 20.
An update broke somethingsudo filebox-update rollback
Disk getting full or failingThe admin dashboard shows disk usage and drive health.
Backups. filebox does not back up the files. A copy of /srv/sftp on another disk is your responsibility.

What is exposed

  • Public: port 2222 (SFTP, family accounts only, locked into their own folder) and port 443 (the web portal).
  • Not public: the admin panel (Tailscale only) and SSH on port 22 (Tailscale, and your home network until you close it in step 8).
  • Repeated wrong passwords are slowed by the portal itself and then banned at the firewall by fail2ban.
  • Passwords are never stored by the web portal. It asks the system to check the same password SFTP uses.
  • Keep the box updated: run sudo apt update && sudo apt upgrade now and then, and sudo filebox-update when there is a new release.
